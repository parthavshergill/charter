# The `attention` encoder

A PufferLib encoder for Charter's observation tables (`rl/layout.json`, layout version 2). PufferLib's MinGRU and
linear decoder follow it, unchanged.

For one observation:

1. The one-row tables (`global`, `proposal`) give the context `c`: one linear map and a ReLU, width 32.
2. Each row of the other tables (seats, resources, kinds, spots, laws, places: 314 rows) is a token: a linear map
   per table and a ReLU, width 32. A row whose `real` column is 0 is padding.
3. Eight heads. Each head asks one question, made from the context (`q = Wq c`). It scores every real token, takes
   a softmax over the real tokens only, and returns the weighted sum of their values. A head with no real token
   returns 0.
4. The heads' answers and `c` go through one linear map to the trainer's hidden size.

No biases: column 0 (`real`) is 1 on every real row, so it acts as one.

Layout 2: 28,064 encoder weights, 143.4K for the whole policy at hidden 128 (layout 1: 26,592 and 165K).

| File | What it is |
|---|---|
| `attention.cu` | The CUDA encoder, with hand-written gradients. `patches/0001-attention-encoder.patch` includes it from `src/ocean.cu` |
| `puffer_build.sh` | The harness's build hook: checks `attention_layout.h` against the layout, copies the encoder into `ocean/charter/` |
| `attention_ref.py` | The PyTorch version, the reference |
| `attention_plan.py` | Sizes, where the tables are, and the weights' shapes and order (the checkpoint's order) |
| `attention_np.py`, `policy.py` | The NumPy forward `rl/eval` uses, format `puffer-attention` |
| `attention_layout.h` | Generated by `gen_layout.py` from `rl/layout.json` |
| `reference_test.py`, `attention_test.cu`, `modal_reftest.py` | The reference test, see its docstring. It runs on Modal with real observations |
| `bc_attention.py` | Behaviour cloning of `hand` into this policy, for a warm start (`modal_app.py --action bc`) |

```bash
cd rl && CHARTER_RL_NAME=attention2 CHARTER_RL_GPU=L4 modal run arch/attention/modal_reftest.py
python3 rl/arch/attention/gen_layout.py rl/layout.json rl/arch/attention/attention_layout.h
cd rl && modal run modal_app.py --action bc --run <you>/bc --games 400 --train-args "--epochs 6 --declare-always"
cd rl && modal run --detach modal_app.py --action train --encoder attention --run <you>/long --resume --cpus 16 \
  --minutes 170 --max-dollars 5 --train-args "--vec.num_threads=16 --train.total_timesteps=500_000_000 \
  --base.warm_start_path=/vol/<you>/bc/bc.bin --train.learning_rate=0.0005 --train.ent_coef=0.001 --env.declare_always=1"
```

Notes:
- With 314 tokens the float32 backward needs about 66 KB of shared memory per block, over a T4's 64 KB, so the
  float32 reference test runs on an L4. Training uses bf16 (about 45 KB) and runs on a T4.
- `--resume` makes a run restartable: attempt k writes `ckpt/a<k>/`, and a new attempt warm-starts from the newest
  checkpoint with the steps left. The volume is committed every 5 minutes.
- `--action train-many` runs several trainings in one container, built once. CUDA graphs are turned off there,
  because they fail to instantiate when trainers share a GPU. At layout 2 a trainer with 1536 agents uses about
  8 GB of GPU memory, so pack 2 per L4.
